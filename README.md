# MicroTeslaController

اپلیکیشن بومی Android با رابط فارسی برای نمایش داده‌های کنترلر ESP32 (حالت Access Point) و تنظیم دو کانال کنترل TC و DS1، مطابق با firmware جدید `MicroTeslaControl`. اپ بدون کتابخانهٔ runtime خارجی ساخته شده و `minSdk 23`، `targetSdk 35`، Kotlin 2.0.21، AGP 8.6.1، Gradle 8.7 و Java 17 دارد.

## اتصال و استفاده

1. در Arduino IDE فایل `firmware/MicroTeslaControl/MicroTeslaControl.ino` را باز کنید و روی ESP32 بارگذاری کنید. وابستگی‌ها: ESP32 Arduino core، OneWire، DallasTemperature، Adafruit GFX Library، Adafruit ILI9341 و کتابخانهٔ MAX6675 سازگار با `MAX6675.h`.
2. به Wi‑Fi با نام `MICROTESLA` و رمز `123456789` (کانال ۶) وصل شوید. برنامه رمز Wi‑Fi را دریافت یا ذخیره نمی‌کند و فرایند ثبت‌نام خودکار ندارد. دکمهٔ «بازکردن تنظیمات Wi‑Fi» تنظیمات سیستم را باز می‌کند.
3. نشانی پیش‌فرض `192.168.4.1` است. فقط IPv4 یا hostname با پورت اختیاری پذیرفته می‌شود؛ مسیر، query، userinfo و URL کامل پذیرفته نیستند.
4. firmware علاوه بر API، یک پنل مرورگری در مسیر ریشه (`/`) هم سرو می‌کند؛ برای تست سریع با مرورگر گوشی قابل استفاده است.

## منطق کنترل (مهم)

رله با منطق هیتر (گرمایش) کار می‌کند و هیسترزیس آن **ثابت ۱°C داخل firmware** است و از برنامه یا `/set` قابل تغییر نیست:

- رله **روشن** می‌شود وقتی دما `<= setpoint − 1.0` باشد.
- رله **خاموش** می‌شود وقتی دما `>= setpoint` باشد.
- مثال: setpoint = 100 و هیسترزیس ثابت ۱ → دما در **۹۹** رله روشن می‌شود و در **۱۰۰** خاموش می‌شود.
- اگر سنسور کانال نامعتبر باشد یا setpoint تنظیم نشده باشد، خروجی آن کانال صریحاً خاموش می‌شود. جهت فیزیکی رله (روشن با HIGH یا LOW) به `RELAY_ACTIVE_LOW` در firmware بستگی دارد که در حال حاضر `false` است.

## محدودیت‌های firmware

- **تنظیم‌ها پس از ری‌بوت ESP32 ذخیره نمی‌شوند** و دوباره باید از برنامه (یا پنل مرورگر) اعمال شوند. برنامه پس از اعمال موفق و تأییدشده، مقدار را در Preferences خود ذخیره می‌کند اما این فقط برای راحتی تایپ است، نه ماندگاری در دستگاه.
- هیسترزیس پارامتر قابل تنظیم نیست؛ مقدار ثابت `HYSTERESIS_C = 1.0` در firmware است. برنامه نیز فیلد هیسترزیس ندارد.
- بازهٔ مجاز: TC از ۰ تا ۱۰۲۴°C و DS از ‎−۵۵ تا ۱۲۵°C؛ مقدار خارج از بازه یا سنسور قطع در `/data` به‌صورت `null` برمی‌گردد و در اپ به شکل `--` نمایش داده می‌شود.

## رفتار برنامه

- پایش: هر ۱٫۵ ثانیه یک `GET /data` (فاصله از پایان درخواست قبلی تا شروع بعدی) با پیاده‌سازی `Handler` و `Executors.newSingleThreadExecutor`. دکمهٔ اتصال، پایش را شروع/متوقف می‌کند؛ توقف همیشه مجاز است.
- مسیر شبکه: درخواست‌ها به شبکهٔ Wi‑Fi گوشی (`TRANSPORT_WIFI` از طریق `ConnectivityManager`) مقید می‌شوند تا با وجود نداشتن اینترنت در AP دستگاه، روی Wi‑Fi ارسال شوند. اگر شبکهٔ Wi‑Fi در سیستم دیده نشود، برنامه پیام راهنمای فارسی نشان می‌دهد و همچنان روی اتصال پیش‌فرض تلاش می‌کند. در بعضی سازندگان ممکن است سیستم شبکهٔ بدون اینترنت را قطع کند؛ در تنظیمات Wi‑Fi گزینهٔ ماندن روی شبکهٔ محلی را فعال کنید. پایش هنگام خروج از صفحه متوقف و با بازگشت فقط در صورت شروع دستی ادامه می‌یابد.
- خوانش‌ها: دماهای TC/DS1/DS2 (null → `--`)، وضعیت خروجی‌ها به شکل «روشن/خاموش»، آرایهٔ ۷ ورودی با برچسب «کلید ۱..۷» (مقدار ۱ یعنی کلید فشرده/پین LOW)، و «مقدار تنظیم‌شده در دستگاه» از `setpoints_C`. خط زیرنویس نیز `ap.ssid`، `ap.ip` و `ap.secure` را نشان می‌دهد.
- تنظیم: فقط دو فیلد عددی TC و DS1 با برچسب دائمی فارسی. هر دو فیلد اختیاری‌اند؛ هر کدام که مقدار داشته باشد ارسال می‌شود و هر دو خالی یعنی خطای «حداقل یکی را وارد کنید». بازه‌ها با پیام خطای فارسی صریح اعتبارسنجی می‌شوند و ارقام فارسی/عربی هم پذیرفته است. درخواست به‌صورت `/set?tc=...&ds=...` با مقادیر URL-encoded ارسال می‌شود.
- Dirty-guard: فیلدهای ویرایش فقط از اولین پاسخ موفق `/data` مقداردهی می‌شوند (و آن هم اگر خالی باشند)؛ پاسخ‌های بعدی بازنویسی‌شان نمی‌کند. پس از اعمال موفق و تأیید، مقدار در Preferences ذخیره می‌شود.
- تأیید اعمال: پس از پاسخ `ok:true` از `/set`، برنامه یک poll جدید `/data` می‌گیرد و بازتاب setpointها را با tolerance ۰٫۰۱ تطبیق می‌دهد؛ فقط در صورت تطبیق پیام «تنظیمات اعمال و تأیید شد» نشان داده می‌شود. خطای HTTP 400 یا `ok:false` به‌صورت متن `error` فارغ‌العنان به کاربر نمایش داده می‌شود.

## API

- `GET /data` پاسخ JSON با این ساختار دارد:
  - `tc_C`, `ds1_C`, `ds2_C`: عدد با دو رقم اعشار یا `null` برای مقدار نامعتبر/خارج از بازه.
  - `inputs`: آرایهٔ ۷تایی از 0/1 (۱ = کلید فشرده؛ پین‌ها با pull-up و فشردن = LOW) و `input_pins` = `[15,2,0,4,16,17,5]`.
  - `outputs`: `{"tc":0/1,"ds1":0/1}`.
  - `setpoints_C`: `{"tc":number|null,"ds1":number|null}`.
  - `ap`: `{"ssid":"MICROTESLA","ip":"192.168.4.1","secure":true|false}`.
- `GET /set?tc=VAL&ds=VAL`: هر دو پارامتر اختیاری‌اند اما حداقل یکی لازم است. موفق: HTTP 200 با `{"ok":true,"message":"setpoint updated"}`. خطای اعتبارسنجی: HTTP 400 با `{"ok":false,"error":"..."}` و هیچ تغییری اعمال نمی‌شود.
- HTTP cleartext برای اتصال محلی در Manifest مجاز است. این API احراز هویت یا رمزنگاری ندارد؛ فقط در شبکهٔ مورد اعتماد استفاده شود.

## ساخت Android

برای ساخت محلی Android Studio، JDK 17 و Android SDK Platform 35 لازم است. در تنظیمات Gradle از نصب محلی Gradle 8.7 استفاده کنید؛ wrapper در این پروژه وجود ندارد. دستور دقیق ساخت از ریشهٔ پروژه:

```sh
gradle :app:assembleDebug
```

دریافت Android Gradle Plugin/Gradle/SDK ممکن است برای اولین ساخت به اینترنت نیاز داشته باشد. اینترنت در زمان اجرای برنامه لازم نیست؛ ارتباط دستگاه با ESP32 محلی و HTTP است. خروجی debug در `app/build/outputs/apk/debug/app-debug.apk` قرار می‌گیرد.

## ساخت با GitHub Actions

برای مخزن تازه، فایل‌های ZIP را استخراج کنید و **محتویات پوشهٔ `MicroTeslaController`، از جمله پوشهٔ مخفی `.github`** را به ریشهٔ مخزن GitHub بارگذاری کنید. بارگذاری خود فایل ZIP به تنهایی workflow را اجرا نمی‌کند. Workflow `.github/workflows/android.yml` اجرا می‌شود با push، pull request یا دستی از **Actions → Build Android → Run workflow**. مراحل workflow: Java 17، `android-actions/setup-android@v3`، نصب `platforms;android-35` و `build-tools;35.0.0`، Gradle 8.7 و `gradle --no-daemon :app:assembleDebug`. پس از اتمام، از اجرای workflow بخش **Artifacts**، `MicroTeslaController-debug-apk` را دریافت و ZIP artifact را استخراج کنید؛ سپس APK را روی گوشی نصب کنید.

## عیب‌یابی

- **اتصال ممکن نشد:** مطمئن شوید Wi‑Fi گوشی به `MICROTESLA` با رمز `123456789` وصل است و آدرس `192.168.4.1` را وارد کرده‌اید. در مرورگر گوشی `http://192.168.4.1/` را باز کنید؛ اگر پنل مرورگر باز شد ولی اپ وصل نشد، مسیر شبکه در اپ را بررسی کنید (پیام خطای اپ راهنمای مسیر Wi‑Fi می‌دهد).
- **پیام «شبکهٔ Wi‑Fi در دسترس نیست»:** در بعضی گوشی‌ها باید روی شبکهٔ بدون اینترنت بمانید؛ در تنظیمات پیشرفتهٔ همان Wi‑Fi گزینهٔ «اتصال خودکار/ماندن روی شبکه» را فعال کنید.
- **مقدار `--` برای دما:** یعنی سنسور آن کانال نامعتبر یا خارج از بازه است (null از firmware). اتصال سیم سنسور و بازهٔ مجاز (TC ۰–۱۰۲۴، DS ‎−۵۵ تا ۱۲۵) را بررسی کنید.
- **خطای HTTP 400 هنگام تنظیم:** مقدار خارج از بازه یا فرمت نامعتبر است؛ متن `error` firmware در status نمایش داده می‌شود.
- **پس از ری‌بوت دستگاه تنظیم‌ها پاک شد:** طبیعی است؛ firmware setpoint را ذخیره نمی‌کند. دوباره از اپ اعمال کنید.
- **رله برعکس عمل می‌کند:** ثابت `RELAY_ACTIVE_LOW` در firmware را با نوع ماژول رله تنظیم کنید.
